# Резервные копии

На сервере из папки проекта:

```bash
bash scripts/backup.sh
```

Формат PostgreSQL custom dump, проверка pg_restore --list, SHA256. Сначала пишется `.partial`, после успеха атомарно переименовывается. Единственная рабочая копия никогда автоматически не удаляется. Копию и .env храните также вне EC2: копия только на том же EBS не защищает от потери диска. Ротация/внешнее хранилище в этой версии не настроены.

Опциональное ежедневное копирование в 03:00 UTC через systemd: `bash scripts/enable-backup-timer.sh`. Оно включается только явным запуском скрипта. Статус: `sudo systemctl status tiktok-traffic-backup.timer`; журнал: `sudo journalctl -u tiktok-traffic-backup.service`. Копии, созданные таймером, могут принадлежать root; скачивайте их с соответствующими правами. Не удаляйте единственную проверенную копию.

Проверочное восстановление:

```bash
bash scripts/restore.sh traffic-YYYYMMDDTHHMMSSZ-PID.dump
```

Введите RESTORE_TEST. Будет создана отдельная БД traffic_restore; существующая с таким именем не перезаписывается. Рабочая traffic не изменяется. Проверьте таблицы, данные и совместимость кода отдельно. Автоматическое destructive restore production через UI отсутствует.

Откат после неудачной миграции: остановить app и optional workers, сохранить текущую БД, восстановить pre-update dump в новую БД, проверить и только затем переключить подключение на неё. Не запускайте старый код поверх новой схемы вслепую. `docker compose down -v` не используется.
