# TikTok Traffic Admin — Neon v2

Русскоязычная админка для ручной редакторской работы: собственные TikTok-аккаунты в реестре, авторы, видео, кампании, подготовка ответов, проверка и подтверждение ручной публикации. Статистика берётся из БД, внешние данные не выдумываются.

Это расширение первой версии. Существующие таблицы `items` и `audit` сохраняются и доступны в разделе «Архив первой версии». Пароль администратора при первом запуске берётся из прежнего `.env`, далее хранится как Argon2id-хеш. Секреты не входят в Git.

## Важное ограничение TikTok

Добавить аккаунт в реестр **не означает войти в TikTok**. Программа не запрашивает пароли TikTok, не управляет браузерными сессиями и не переключает аккаунты. OAuth TikTok в этой версии не реализован. Официальные API управления комментариями собственных видео требуют отдельного приложения и разрешений. Автоматическая рассылка похожих рекламных ответов под чужими видео отсутствует.

Рабочий процесс: добавить аккаунт → кампанию → видео → исходный комментарий → черновик → взять в работу → редактировать / подготовить AI → одобрить → открыть видео → вручную войти в нужный TikTok-аккаунт и опубликовать уместный ответ → подтвердить ручную публикацию и указать ссылку. Система фиксирует заявление оператора; наличие публикации на TikTok она не проверяет.

## Реализованный код

- Next.js static export, React, TypeScript, Tailwind, Lucide, Recharts, TanStack Query, React Hook Form и Zod. Тёмная палитра, неоновые акценты, формы, таблицы, поиск, пагинация, ошибки, пустые состояния и отключение анимации.
- FastAPI, SQLAlchemy Core 2, Alembic, PostgreSQL 16, миграция новых таблиц с сохранением старых.
- Авторизация через сессии в HttpOnly cookie, CSRF, Argon2id, пять ролей, журнал действий; администратор создаётся только один раз.
- CRUD аккаунтов, авторов, видео, исходных комментариев, кампаний, каналов и расписаний. Уникальные ограничения и внешние ключи БД.
- Очередь ручных черновиков: атомарное резервирование, одобрение, отклонение, освобождение, запись результата и запрет повторного подтверждения.
- Опциональный Redis/Celery: проверка ресурсов и синхронизация Telegram, периодический диспетчер, ограниченные повторы, отмена ожидающей задачи, восстановление по аренде. Ошибки остаются в FAILED до проверки оператором.
- Telegram: проверка прав бота, создание пригласительных ссылок, собственный редирект переходов, polling событий вступления/выхода, дедупликация update_id, псевдонимизация Telegram user ID.
- AI: отдельные адаптеры OpenAI Responses и Gemini generateContent для одного черновика по предоставленному описанию; ручной режим без ключа, суточный лимит запросов, журнал токенов и ошибок. Результат не публикуется автоматически.
- CSV-экспорт, CSV-импорт авторов/видео, отчёты XLSX/PDF, журнал, уведомления о новых черновиках и нехватке диска, центр ошибок фоновых задач.
- Скрипты установки, проверки ресурсов, запуска, обновления, диагностики, копирования БД и пробного восстановления в отдельную БД.

Полный статус соответствия большому ТЗ — [COVERAGE.md](COVERAGE.md). Наличие исходников не означает, что все интеграции проверены с реальными ключами. Фактические проверки — [CHECKS.md](CHECKS.md) и GitHub Actions.

## Ресурсы и запуск

Ubuntu 24.04, amd64/arm64; минимум 2 ГБ RAM, рекомендуется 4 ГБ для сборки Next.js; не менее 5 ГБ свободного диска перед сборкой, ориентир EBS 30 ГБ. Сборка должна завершиться до развёртывания; при нехватке памяти используйте более мощную сборочную машину, а не скрытую автоматическую очистку.

Для новой установки в терминале Ubuntu:

```bash
git clone --branch neon-v2 https://github.com/shomurzaev200/tiktok-traffic-admin.git
cd tiktok-traffic-admin
bash scripts/install.sh
```

Пароли создаются в `.env`. Для доступа через порт, выбранного в этой переписке, добавьте `APP_HOST=0.0.0.0` в `.env`, затем `sudo docker compose up -d --wait`. В AWS Security Group разрешите Custom TCP 8000 только с My IP. Адрес: `http://PUBLIC_IP:8000`. HTTP не шифрует пароль; для обычного публичного развёртывания настройте HTTPS. `COOKIE_SECURE=true` включайте только при HTTPS.

После запуска:

```bash
bash scripts/healthcheck.sh
sudo docker compose exec -T app python < scripts/smoke_v2.py
```

Smoke создаёт помеченные тестовые записи и не отправляет ничего в TikTok.

## Обновление существующего сервера

Не выполняйте `git pull` поверх локального изменения порта вслепую. Порядок с резервной копией и переносом настройки в APP_HOST — в [DEPLOY.md](DEPLOY.md). Не удаляйте `.env` или PostgreSQL volume.

## Первый вход

Откройте админку. Логин — ADMIN_USER, пароль — ADMIN_PASSWORD из `.env` при первом bootstrap. После создания пользователей изменение переменной не меняет хеш пользователя. SUPER_ADMIN может создавать пользователей и завершать сессии через API; действия доступны с учётом роли.

## Telegram

1. Создайте бота в BotFather и добавьте администратором канала с правом приглашать участников.
2. В `.env`: `TELEGRAM_BOT_TOKEN=...` и `COMPOSE_PROFILES=jobs,integrations`.
3. `sudo docker compose up -d --build --wait`.
4. Добавьте канал с числовым chat_id `-100…`, нажмите «Проверить права бота».
5. Назначьте канал кампании и создайте пригласительную ссылку. Для переходов используйте `/r/SLUG` на вашем сервере.

Запускайте только один polling-процесс на токен, отключите другой бот/старый webhook, если используете этот polling. Полная история подписчиков недоступна: учитываются только события, полученные ботом после включения. При остановке надолго Telegram может уже не хранить пропущенные события. Счётчик канала и события имеют разную семантику. Повторные вступления не считаются новыми уникальными людьми в метрике joins. HTTP-переходы не равны уникальным людям. Разные каналы и короткие периоды нельзя использовать для достоверного удержания без дополнительных данных.

## AI

В `.env` задайте `AI_PROVIDER=openai` или `gemini`, `AI_MODEL` — доступную вам модель, и соответствующий `OPENAI_API_KEY` или `GEMINI_API_KEY`. При `AI_PROVIDER=manual` внешних запросов нет. Примените `sudo docker compose up -d app`.

Кнопка генерации относится к одному черновику, взятому оператором в работу. Провайдер получает только описание видео и текст исходного комментария. Изображение/звук видео не скачиваются и не анализируются. По умолчанию не более 20 запросов за скользящие 24 часа; FAILED и RESERVED тоже учитываются. Токены записываются из ответа провайдера. Денежный бюджет устанавливайте также у провайдера: денежная оценка/жёсткий финансовый лимит в этой версии не реализованы.
