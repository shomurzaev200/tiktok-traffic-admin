# Покрытие требований V2 — без объявления полной готовности

## Реализовано в исходниках, проверка сборкой и интеграционными тестами обязательна

Сессии, роли, CRUD реестров, редакторский цикл, дедупликация комментария в кампании, резервирование одним оператором, подтверждение ручной публикации, кампании, CSV, Telegram polling и invite links, AI-адаптеры одиночного черновика, фоновые SYSTEM_CHECK/TELEGRAM_SYNC, интервальный планировщик, аудит, основные журналы ошибок, резервное копирование и пробное восстановление, неоновый frontend, GitHub Actions.

## Ограничения реализации относительно полного MASTER PROMPT V2

- Нет TikTok OAuth и автоматической синхронизации профилей/чужих видео/комментариев. Реестр аккаунтов не авторизует TikTok. Публикация только вручную.
- Нет массового спам-комментирования, скрытой ротации, CAPTCHA/proxy bypass.
- Frontend собирается Next.js в статику и обслуживается FastAPI в одном контейнере. Отдельного постоянно работающего frontend Node-сервиса нет, чтобы уменьшить RAM. Компоненты собственные, shadcn/ui не используется.
- Модели — SQLAlchemy Core Table, не ORM-классы. Роли — контролируемый enum приложения. Связь аккаунта/автора с кампанией — один внешний ключ, без M:N campaign_accounts/campaign_creators. Агрегаты считаются из событий, таблицы analytics_daily нет.
- Нет отдельного reverse proxy и автоматического HTTPS в стандартном Compose; прямой порт соответствует выбранной пользователем конфигурации. Публичный HTTP не подходит для передачи чувствительных секретов через недоверенную сеть.
- Реализованы CSV-импорт авторов/видео и отчёты XLSX/PDF; произвольный cron отсутствует. Планировщик поддерживает период в минутах; однократные SYSTEM_CHECK/TELEGRAM_SYNC — через задачи.
- AI анализирует только описание/текст, возвращает один ответ, не анализирует сам видеофайл. Нет денежного бюджетирования и автоматической проверки правдивости. Только лимит запросов и учёт токенов. Ни один провайдер с реальным ключом не проверен без предоставления конфигурации.
- Нет Telegram-уведомлений администратору, полной истории подписчиков, доказанного удержания, полноценной модели атрибуции всех источников. Аналитика событий и ручные отчёты разделены.
- Нет Webhook/SMTP/произвольных интеграций и шифрования секретов, сохраняемых из UI: ввод секретов через UI вообще отсутствует. Секреты только в .env на сервере.
- Экран бэкапов не выдаёт Docker-доступ веб-приложению. Backup/restore выполняются безопасными CLI-скриптами; расписание и автоматическая ротация бэкапов пока отсутствуют. Метаданные backup_records регистрируются при доступном app, но сама копия создаётся независимо от app.
- Уведомления ограничены новыми черновиками и нехваткой диска. Центр ошибок записывает ошибки worker, но не все backend/Telegram/AI исключения в единую модель severity/task/account.
- Есть создание пользователей, изменение роли/блокировка/сброс пароля и отзыв сессий через API и UI. Самостоятельное восстановление пароля по email отсутствует.
- Нет полноценного управления приоритетами Celery, частичной отмены уже выполняющейся работы и отдельной брокерной dead-letter queue. FAILED — список остановленных задач в БД. Повторы ограничены; операции публикации не выполняются worker.
- Нет полноценного мониторинга хоста, Grafana/Prometheus, нагрузочного теста целевых 100 тыс./1 млн записей. Размер диска в UI — контейнерная файловая система, а не отдельный монитор EBS-хоста.
- Нет автоматической установки на EC2 из этой среды; доступ к AWS и реальная диагностика падающего старого контейнера не предоставлены.

Проект не объявлен production-ready или полностью соответствующим всем критериям V2. Проверенный релиз должен иметь успешный CI и проверку на отдельном staging с внешними ключами, резервным копированием и HTTPS.
